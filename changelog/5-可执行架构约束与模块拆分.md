# CADX 可执行架构约束与模块拆分变更记录

> 更新日期：2026-08-07
> 版本：0.5.0

本次更新把 CADX 的分层原则从文档约定升级为可执行的构建契约，并集中拆分多个超大模块。新增的架构门禁会持续检查 workspace 成员归属、依赖方向、技术边界和源码文件规模，使后续扩展必须显式遵守现有模块边界。

## 1. 可执行架构契约

- 新增不参与发布且无第三方依赖的 `cadx-arch` crate；它从磁盘读取 workspace 清单和源码，只影响验证结果，不进入产品运行时。
- 将全部 workspace crate 显式划分为 Geometry、Domain、SPI、Pack、Analysis、Configuration、Application、Infrastructure、Presentation、Composition 和 Contract 层。
- 新增成员必须在 `CRATE_LAYERS` 中且只能归属一个层；已经删除或改名的残留分类也会导致测试失败。
- 依赖审计按照分层矩阵拒绝向外依赖和独立架构列之间的越界依赖，仅组合根可以装配全部具体实现。

## 2. 技术边界检查

- 架构测试检查各层运行时依赖中的第三方技术前缀，防止内层代码直接引入 UI、GPU、具体几何内核、AI Provider 或文件系统实现。
- Geometry、Domain、SPI、Pack 和 Analysis 保持对 egui/wgpu、Truck、genai/Tokio 及文件系统实现的隔离。
- Infrastructure 可以拥有具体内核和 Provider，但不能依赖 UI；Presentation 可以拥有 GPU，但不能依赖具体内核或 Provider。
- 依赖检查只审计运行时依赖，允许 adapter 的 conformance 测试通过开发依赖复用交换格式等测试能力。

## 3. 架构债务棘轮

- 新增 `PENDING_INVERSION`，记录现存但已安排反转的越层依赖；当前显式跟踪 `cadx-app -> cadx-io` 的 STEP DTO 依赖。
- 新增 `PENDING_DECOMPOSITION`，集中记录启用文件预算前已经存在的超限源码文件。
- 两份清单都包含陈旧项检测：一旦对应依赖已经反转或文件已经完成拆分，测试会要求删除豁免，避免临时债务永久留存。
- 新增或扩大豁免被定义为架构决策，必须同步记录原因和计划处理方式。

## 4. 源码文件预算

- 对每个 workspace 成员的 `src/` 和 `tests/` 目录递归执行 Rust 文件行数检查，单文件上限固定为 1000 行。
- 超限报告按文件规模从大到小排序，并使用 workspace 相对路径输出，便于直接定位和逐项处理。
- crate 根文件收敛为模块声明与公共重导出表面，持续增长的实现必须拆入具名、职责内聚的子模块，而不是提高预算。

## 5. 大模块拆分

- `cadx-sketch` 按约束、几何、参数、投影、交点、残差、求解器、诊断和测试支持拆分，保留统一的公共 API 导出。
- `cadx-ai::genai` 按客户端、文档视图、错误、提示词和 JSON Schema 拆分，Schema 定义及测试进一步独立组织。
- `cadx-app` 将 CoreBus 事件和 DocumentSession 预览、测试支持拆入子模块，事务入口继续由原模块路径统一暴露。
- `cadx-core::assembly` 按组件、mate、变换和校验拆分；`cadx-io::step` 按 AST、编码、单位、颜色、实体和装配图/位姿拆分。
- `cadx-domain-api` 将动作、上下文、扩展、问题、清单、领域包、注册表和 Schema 契约分离。
- MCAD、AEC 和 ECAD 聚合包将能力声明、工具目录、执行逻辑及领域估算拆出，使 crate 根保持为清晰的组装与重导出入口。

## 6. 文档与验证入口

- 新增 `docs/module-map.md`，集中记录架构层、允许依赖、禁止技术、债务棘轮和文件预算，作为源码位置与机器规则的结构化索引。
- README 和架构文档补充 `cadx-arch` 的职责、新 crate 接入要求、模块根约束以及架构门禁说明。
- 验证流程新增 `cargo test -p cadx-arch`，用于在完整格式化、Clippy 和 workspace 测试前快速发现结构性回归。
- 新增 workspace 发现、Cargo 清单解析、依赖分层、禁止技术、成员分类、文件预算和豁免陈旧性测试。
