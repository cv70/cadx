# ADR-0004：PromptChangeSet 与补偿回滚

> 文档类型：架构决策记录
> 状态：Accepted
> 适用范围：Target
> 权威内容：为何采用实时 action 提交和冲突感知补偿
> 返回：[文档索引](../index.md) · [ADR 索引](README.md)

## 背景

长时间 Agent 任务可能包含许多独立设计动作。把整句 Prompt 当成一个跨分钟或跨小时的原子事务，会隐藏有效中间结果、扩大锁范围，并让崩溃恢复和人工介入变得困难。另一方面，用户仍需要按原始意图查看和撤销一组改动。

当其他 Prompt 或人工编辑已经修改相同对象时，直接应用旧 reverse patch 会覆盖较新工作。

## 决定

每个通过本地验证的 action 立即成为独立 `ActionCommit`。一句 Prompt 创建一个 `PromptChangeSet`，只负责归组、归因、进度、错误和整体回滚入口，不提供跨 action 的 ACID 原子性。ChangeSet 可以完成、部分失败或取消，已经成功的 action 都保留。

本地提交在 action 边界串行化，不同 `PromptChangeSet` 的 action 可以交错。每个 `SemanticOperation` 携带对象版本前置条件和幂等键；发现版本过期时，运行时重新观察并规划，自动修复最多三次。超过上限后 action 失败并保留稳定诊断，不覆盖新版本。

回滚创建新的补偿 ChangeSet。内核只自动恢复自原 action 后未被修改的对象；发生后续修改的对象进入冲突报告。无冲突部分仍可提交，因此结果可能是完全回滚或带冲突回滚。历史提交不删除，branch head 不向过去移动。

## 接口影响

- `PromptChangeSet` 记录 Prompt、结构化目标、运行身份、授权、action/commit 列表、诊断和状态。
- `ActionCommit` 记录操作、父 revision、对象读写版本、diff、本地 evidence、actor 和 ChangeSet 来源。
- 每个操作具有稳定 `idempotency_key`；重复提交必须返回原结果或明确冲突。
- 补偿操作使用与普通写入相同的能力、前置条件和验证闸门。
- reverse patch 只能作为经 hash 校验的缓存；事件和快照仍是恢复依据。

## 替代方案

- **整句 Prompt 全有或全无**：拒绝。长事务不适合异步 Agent、实时反馈和崩溃恢复。
- **回滚时直接移动历史头**：拒绝。会丢失后续人工或其他任务的工作及审计顺序。
- **无条件应用逆向补丁**：拒绝。会静默覆盖对象的新版本。
- **每个 Prompt 独占整个工程**：拒绝。它阻止独立任务交错，并产生不必要的等待。

## 后果

用户能持续看到可靠进展，任务失败不会抹去有效工作，崩溃恢复也只需从最后提交继续。代价是“撤销一句 Prompt”可能产生冲突，UI 和 Agent 必须展示部分成功、部分回滚及待人工解决对象。

## 安全限制

补偿不是越权入口。原授权已撤销、对象现由更严格策略保护或 Pack 版本不匹配时，回滚可以被拒绝并要求人工处理。审计界面不能把 `RevertedWithConflicts` 表示成完全撤销。
