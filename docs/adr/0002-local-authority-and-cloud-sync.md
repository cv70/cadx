# ADR-0002：本地权威与云端同步

> 文档类型：架构决策记录
> 状态：Accepted
> 适用范围：Target
> 权威内容：为何本地内核拥有最终提交权及 v1 同步边界
> 返回：[文档索引](../index.md) · [ADR 索引](README.md)

## 背景

CAD 编辑需要低延迟、离线可用和对私有工程数据的明确控制。云端可以提供模型推理、重计算和协作存储，但若云端同时成为模型权威，网络可用性、服务版本和租户边界都会进入每次本地编辑的可信计算基。

多主 CAD 语义合并还涉及参数依赖、稳定拓扑引用和制造规则，不能等同于文本或普通键值 CRDT。

## 决定

本地 `KernelFacade` 是唯一提交权威。人工工具、Agent、远程模型和云端计算都只能提交候选语义操作；本地内核按工程版本锁重新准备、验证并提交。设备断网时保留完整编辑、验证、历史和发布能力。

云端只保存或传递不可变提交、快照、内容寻址 blob、分支引用和 Release 证明，也可以返回候选计算结果。远程结果在本地重验前不属于权威工程状态。

第一版同步使用单写者分支：一个分支同一时刻只允许一个获租约设备写入。分支头更新采用 expected-parent compare-and-swap；父提交不匹配时拒绝推送。离线或并行工作创建独立分支，协作提升以完整分支为单位，不提供实时多主、对象级 CRDT 或自动语义 merge。

同一设备上不同 `PromptChangeSet` 的 action 可以在提交边界交错，但所有本地提交由一个协调器串行化，并受对象版本前置条件约束。

## 接口影响

- 每个提交必须包含稳定 `RevisionId`、父提交、分支和状态 hash。
- 同步 API 必须显式传递 `branch_id`、`expected_parent` 和新的不可变提交引用。
- 分支租约、拒绝原因和提升操作进入审计历史，不能由客户端静默覆盖。
- 云端 evidence 和派生几何使用候选/不受信状态，不能直接写本地 branch head。

## 替代方案

- **服务端权威提交**：拒绝。它破坏离线能力，并扩大数据与版本依赖的可信边界。
- **第一版即实时多主语义 merge**：拒绝。稳定引用和依赖图冲突尚不足以支持无损自动合并。
- **完全无云端能力**：拒绝。不可变复制、备份、异步计算和受控协作仍有明确价值。

## 后果

提交行为可预测，网络故障不会阻断设计工作，远程服务也不能单方面制造已接受提交。代价是跨设备并发会产生显式分支，用户需要评审并提升一个完整结果；细粒度语义合并留给后续独立设计。

## 安全限制

本地权威不能防止恶意云端删除、延迟或回放数据。同步仍需传输加密、身份认证、租约校验、哈希验证和重放防护。若本地 Core 或已加载原生 Pack 被攻破，本地验证边界也随之失效。
