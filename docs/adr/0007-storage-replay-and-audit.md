# ADR-0007：存储、重放与审计

> 文档类型：架构决策记录
> 状态：Accepted
> 适用范围：Target
> 权威内容：为何采用 SQLite/WAL、内容寻址存储和版本锁重放
> 返回：[文档索引](../index.md) · [ADR 索引](README.md)

## 背景

完整 MCAD 工程包含大量提交、依赖、B-rep、网格、附件和验证证据。单一 JSON 文档难以提供增量事务、并发读取、局部恢复和大 blob 去重。只保存 reverse patch 会把恢复正确性绑定到每个逆操作；每次保存完整快照则会快速放大空间和 I/O。

几何内核、求解器和规则升级还会改变浮点细节或拓扑表示，因此“任何版本都逐字节重放一致”不是可维护承诺。

## 决定

工作工程使用 SQLite/WAL 保存事务元数据、对象版本、事件、分支、PromptChangeSet、验证证据和审计索引。B-rep、网格、附件和大快照存入内容寻址 blob store，数据库只引用已校验 hash。权威恢复依据是前向事件日志加周期快照；reverse patch 仅作可丢弃、可校验的性能缓存。

`.cadx` 定义为可移植封包，用于交换、归档和备份，而不是编辑期唯一存储。封包包含 manifest、所需事件/快照、blob、`PackLock`、审计链和可选 Release。导入先校验条目 allowlist、大小、hash、schema 和重放结果，再原子提升。

确定性以 `PackLock` 为边界：相同锁、输入和事件序列必须得到相同规范化语义 state hash。非权威派生物不进入该 hash。跨 Core、Pack 或 OCCT 版本只承诺经过显式迁移和复验的语义等价，包括可编辑结构、约束、关键测量、引用和发布规则；不承诺 B-rep 字节或浮点路径一致。

提交按父 hash 形成哈希链，证据、blob 和 Pack artifact 由内容 hash 引用。Release 再对固定 revision、state hash、版本锁和 evidence 集合进行用户或设备签名。

## 接口影响

- 存储层需要事务 journal、周期快照、CAS blob、垃圾回收根和崩溃恢复协议。
- `PackLock` 必须固定所有影响重放、再生和验证的依赖；完整锁定集合由[目标设计](../design.md)定义。
- 迁移器在隔离 candidate 上运行，输出新的迁移提交和验证证据，不能原地改写旧事件。
- state hash 使用规范化语义编码、稳定排序和明确排除项。
- `.cadx` 导入导出必须有资源上限、路径/条目 allowlist 和原子失败行为。

## 替代方案

- **单一 JSON 或压缩 JSON 作为工作存储**：拒绝。无法良好支撑大工程增量写入和 blob 生命周期。
- **每个提交保存完整快照**：拒绝。空间和写放大不可接受。
- **只依赖逆向补丁恢复**：拒绝。逆操作缺陷会破坏权威历史。
- **跨所有版本承诺位级确定**：拒绝。几何内核与平台演进使该承诺不现实，也会阻碍安全升级。

## 后果

本地写入可事务化，崩溃恢复和大对象去重有明确基础，可移植包也不再限制编辑期性能。代价是需要管理 SQLite schema、blob 垃圾回收、快照压缩、Pack 版本获取和迁移验证；语义 hash 规范必须长期稳定。

## 安全限制

哈希链只能让篡改可见，不能证明 actor 身份或阻止删除整个历史；签名和外部备份分别承担认证与可用性。导入不受信 `.cadx` 时仍需严格资源限制，Pack artifact 不能因为随封包提供就自动获得执行信任。
